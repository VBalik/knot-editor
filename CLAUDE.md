# Редактор топологических узлов (knot-editor)

Отвечай пользователю только на русском: отчёты, статусы, вопросы. Интерфейс программы и сообщения коммитов остаются на английском.
**Названия настроек, меню и пунктов интерфейса — всегда по-английски, без перевода** (macOS, браузер, любые программы): у пользователя система на английском, перевод названий мешает их найти. Пиши «System Settings → Privacy & Security → Full Disk Access», а не русский вариант.

## Что это
Одностраничное веб-приложение `index.html` (three.js r128 с CDN, без сборки): 2D-редактор диаграммы узла (рисование мышью, Random, загрузка картинки или фото кнопкой Image) и 3D-релаксация упругой трубки (L-BFGS, воркеры, WebAssembly-ядро пар). Кнопка Physics — алгоритм P (физика 4.20), кнопка Stir — алгоритм S: в `exp` с 4.21-exp это «бегущая грыжа» (невидимая дышащая сфера диаметром в ширину всего 3D-узла бежит по нити и расталкивает узел, потом P; с 4.22-exp Pause и захват верёвочки снимают S), в `v3` — разжатие тугих контактов 4.20. Полная история решений, физика, интерфейс и все версии — в `PROMPT-v2.md` (читай нужный раздел, а не весь файл: он большой).

## Правила работы
- **Ветка работы — `v3`.** С 2026-09-18 `main` перемотана на `v3` по решению пользователя: свежий клон и новая облачная
  сессия попадают на рабочее дерево, а не на июльскую оболочку. Дальше `main` обновляется только по просьбе (`git push origin v3:main`,
  только перемотка вперёд); помни, что из `main` собирается GitHub Pages, то есть это вторая публикация рядом с Netlify.
- **Две публикации на Netlify (с 2026-10-03, платный тариф).** Рабочая версия: сайт spring-knot.netlify.app публикует ветку `site` (`git push origin v3:site`, только перемотка вперёд, по просьбе). Экспериментальная: ветка `exp` (создана от `v3`) → сайт spring-knot-exp.netlify.app, каждый push в `exp` публикуется автоматически (сборки нет, publish directory — корень). Нумерация: сборки идут в `exp` и прибавляют номер (4.21, 4.22…), в `exp` номер показывается с суффиксом «-exp» (`APP_VER_TAG='-exp'` в `index.html` ветки `exp`; в `v3` — `''`); суффикс вшит в файл, поэтому он виден и на сайте, и в офлайн-копии `Knots-exp`. Перенос в рабочую версию — только по просьбе: `exp` вливается в `v3` (`git merge`), `APP_VER_TAG` ставится `''`, номер сохраняется (4.22-exp → 4.22), затем `v3` → `site` и `main`. Рабочая копия на Mac: папка `Knots` — ветка `v3`, папка `Knots-exp` — ветка `exp` (два клона в Google Drive, обе версии доступны offline).
- **Решение 2026-10-03: лучшая версия — 4.20 (`v3`).** Экспериментальные ветки `v5` (5.0–6.0: simplify, ветвление, ходы Рейдемейстера в 3D, раздельные волны, сферы) и `v7` (7.0–7.1: поток медиальных сфер MSP с точным сертификатом траектории) удалены с GitHub как не давшие выигрыша на узле Хакена (их содержимое сохранено тегами `archive/v5`, `archive/v7`; разбор — в `PROMPT-v2.md` тех веток). `main` = `v3`.
- **Номер версии** растёт на 1 с каждой сборкой программы: `APP_VER_MINOR` в `index.html` и `<span id="appVer">` (сейчас 4.20, дальше 4.21, 4.22…). Изменения только в стенде или документах версию не меняют.
- **Каждая версия** описывается разделом «Версия X.Y» в `PROMPT-v2.md` перед разделом «Проект и публикация»; строка «сейчас X.Y» там же обновляется.
- **Коммиты выборочные:** называй файлы явно, никогда `git add -A` / `git add .`. Не коммитить сломанные состояния: сначала стенд.
- **Картинки пользователя** (фото и рисунки узлов) в репозиторий не добавлять: он публичный (с 2026-10-03 снова public — иначе Netlify отклонял деплои коммитов с автором noreply@anthropic.com).
- **Ползунок Repel ×2 (4.13):** физическое `repCoef = 2×ползунок`; стенд говорит физическими значениями (`harness.setSlider('repCoef', v)` ставит `v/2`).
- Не менять физику молча: `bench.js` должен давать `hashMatch: true`. Хэши зависят от версии Node, поэтому эталоны разные для Air и облака. Если изменение физики задумано, сказать об этом пользователю и обновить эталоны в `test/bench.js` для каждой версии Node, где их можно пересчитать; для недоступной версии эталон удалить и написать об этом.

## Стенд (Node, без браузера)

Запуск: `cd test && node harness.js <тест.js>` — тест печатает JSON, у большинства есть поле `ok`.

## Публикация и проверка
- **Работа** над рабочей версией идёт в `v3` (публикация — `site` по просьбе), над экспериментальной — в `exp` (публикуется каждым push на тестовый сайт).
- **Проверка у пользователя:** он скачивает `v3` на свой Mac и открывает `index.html`. В конце работы напомни ему команду и назови номер версии, который он должен увидеть. Команда — с `cd`, а НЕ `git -C`: в папке Google Drive `git -C` падает с `Unable to read current working directory: Operation not permitted` (файловый провайдер Drive), а после `cd` всё работает:
  ```
  cd "/Users/balik/Library/CloudStorage/GoogleDrive-gbalik@gmail.com/My Drive/Programming/Claude/Knots" && git pull
  ```
- **Репозиторий лежит внутри Google Drive, и это рискованно:** 2026-09-19 `.git` там разъехался с файлами (HEAD показывал v4.0, когда на экране была 4.6). Стоит предложить перенос рабочей копии на обычный диск.

## Облако
В облачной сессии нет живого браузера. **Вид 2D-холста проверяется стендом:** `test/canvas2d.js` — настоящая растеризация Canvas 2D, `draw2d.js` рисует диаграмму в PNG (см. таблицу выше), картинку можно открыть и посмотреть. Всё остальное (вёрстка страницы, кнопки, рамки, 3D, поведение мыши и перетаскивания в живом браузере) стендом не проверяется — честно скажи пользователю, что именно не проверено, и попроси посмотреть в браузере.
